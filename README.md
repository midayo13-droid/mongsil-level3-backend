# 몽실 미용실 예약 관리 – 백엔드 (Level 3)

반려동물 미용실의 **예약·고객·강아지·미용 기록**을 관리하는 서버예요. NestJS + PostgreSQL로 만들었고 **Render**에 올리도록 준비했어요.
Level 1 사이트와 **같은 DB**를 함께 쓰고, Level 3에 필요한 테이블(계정·예약·AI 사용 기록·휴무일·공휴일 기록·공지 첨부파일·이벤트 이미지)만 새로 더해요.
이 서버 하나를 **관리자 화면**(총관리자·일반관리자)과 **고객 화면**이 함께 써요.

- **배포된 서버**: https://mongsil-level3-backend.onrender.com (상태 확인: `/health`)
- 화면(프론트) 주소: https://mongsil-level3-frontend.vercel.app (저장소 `mongsil-level3-frontend`)
- 이 저장소(백엔드): `mongsil-level3-backend`
- 문서: [기획서.md](./기획서.md) · [디자인가이드.md](./디자인가이드.md) · [메뉴구조도_IA.md](./메뉴구조도_IA.md)

> ⏳ **첫 접속이 느릴 수 있어요.**
> Render 무료 서버는 한동안 아무도 쓰지 않으면 잠들어요. 잠든 뒤 처음 접속하면 깨어나는 데 **1분 가까이** 걸릴 수 있어요.
> 화면이 멈춘 것처럼 보여도 잠깐 기다린 뒤 새로고침하면 정상으로 열려요.

## 역할 3단계

| 역할 | 계정 | 설명 |
|---|---|---|
| **총관리자** (사장님) | 1개만 (`master`) | 모든 일. 삭제, 관리사(로그인 계정 포함)·공지·이벤트·휴무일 관리, 고객 계정 보기·삭제, 매출 보기, 가상 데이터 다시 채우기 |
| **일반관리자** (관리사) | 총관리자가 **관리사를 등록할 때 함께** 만듦 (관리사 1명 = 계정 1개) | 조회, 고객·강아지 등록·수정, 주의사항 추가, 미용 기록 등록, 예약 신청·취소, AI 요약 |
| **고객** | 직접 가입 | **내 강아지·내 예약만**. 강아지 정보 수정·추가, 예약 신청·취소, 내 정보 수정, AI 스타일 추천 |

서버가 **모든 요청에서** 출입증(토큰)과 역할을 확인해요. 역할을 따로 적지 않은 주소는 **고객이 열 수 없게 기본값이 막는 쪽**이에요. 고객 전용 주소(`/me/...`)는 항상 "내 보호자·내 강아지·내 예약"으로만 좁혀서 보여 줘요.

## 할 수 있는 일

| 구분 | 내용 |
|---|---|
| 로그인·가입 | 아이디·비밀번호 로그인(8시간 출입증). **고객 가입**은 계정 + 보호자 + 강아지(1~5마리)를 한꺼번에 저장하고, 하나라도 실패하면 아무것도 저장하지 않아요 |
| 예약 신청·취소 | 강아지·관리사·날짜·시간(30분 단위)·스타일. **고객이 신청하면 바로 확정.** 관리사를 `auto`로 보내면 서버가 가장 한가한 사람을 정해요 |
| 예약 현황 | 오늘 예약 수, 이번 달 예약 건수, 이번 달 매출(**총관리자에게만** 값을 보내요). 카드별 그래프용 숫자: 오늘 시간대별 · 달 날짜별 예약 · 달 날짜별 매출(`/stats/series`) |
| 목록 쪽 나누기 | 목록 주소에 `page`·`size`(최대 100)를 보내면 `{ items, total, page, size }`로 돌려줘요. 보내지 않으면 전체 목록이에요 |
| 공지 첨부파일·이벤트 이미지 | 공지당 첨부 3개, 이벤트 이미지 1장(각 5MB 이하)을 DB에 저장해요. 총관리자만 올리고 지울 수 있어요 |
| 가상 데이터 다시 채우기 | 총관리자만. 예약·AI 사용 기록을 지우고 가상 예약으로 다시 채워요. 계정(고객 포함), 휴무일, 고객·강아지 같은 공유 데이터는 지우지 않아요 |
| AI 미용 도우미 | 관리자 화면 역할은 "미용 전 안내 3줄 + 추천 스타일", **고객은 추천 스타일만**(요약은 서버가 보내지 않아요). OpenAI API 사용 |
| 휴무일 | 일요일은 항상 휴무. 공휴일은 무료 공휴일 API([Nager.Date](https://date.nager.at))에서 자동으로 불러오고, 그 밖의 쉬는 날은 총관리자가 직접 등록해요 |

## 서버가 지키는 규칙

**예약** (관리사가 입력해도, 고객이 직접 해도 똑같아요)
- R-1 같은 관리사의 같은 날짜·시간에는 예약 1건만
- R-2 같은 강아지는 같은 날 예약 1건만
- R-3 일요일·휴무일에는 신청 불가
- R-4 지난 날짜·시간 불가, 시간은 10:00~17:30의 30분 단위만
- R-5 관리사 한 명은 하루 최대 6건
- R-6 근무 중인 관리사만 선택 가능
- R-7 취소는 **예약 당일 00:00까지** (예: 10월 30일 예약은 10월 30일 00:00까지, 당일에는 취소 불가). 이미 취소된 예약은 다시 취소 불가
- R-8 **자동 배정**: 그 시간에 비어 있고 그날 6건 미만인 근무 중 관리사 중, 그날 예약이 가장 적은 사람(같으면 번호가 앞선 사람)
- R-9 고객은 **자기 강아지로만** 예약하고 **자기 예약만** 보고 취소할 수 있어요
- R-10 고객은 앞으로의 예약을 동시에 **최대 5건**

**관리사 계정**: 관리사를 등록할 때 로그인 계정(아이디·비밀번호)도 함께 만들 수 있어요. 계정만 따로 만들 수는 없어요. 아이디는 바꿀 수 없고 비밀번호만 새로 정할 수 있어요. **"퇴사"로 바꾸면 로그인할 수 없고**(이미 받은 출입증도 바로 막혀요), 삭제하면 계정도 함께 지워져요.

**가입**: 아이디 영문·숫자 4\~20자(중복 불가), 비밀번호 8자 이상, **이미 등록된 휴대폰 번호면 가입 불가**("이미 등록된 번호예요. 매장에 문의해 주세요"), 없는 번호는 새 보호자로 등록, 강아지 1\~5마리.

**AI**: 로그인한 사람만. 관리자 화면 역할은 하루 20번, 고객은 하루 5번까지. 고객은 내 강아지에게만 쓸 수 있어요. 보호자 이름·전화번호·이메일은 AI에 보내지 않아요. 답을 못 받으면 쉬운 안내를 돌려줘요.

**Level 1에서 이어지는 규칙**: 휴대폰 번호 11자리·고객 번호 중복 금지, 숫자 칸에 글자 금지, 주의사항 수정 불가(삭제만), 강아지가 있는 고객·기록이나 예약이 있는 관리사 삭제 금지, 사진 jpg/png 5MB 이하.

## 확인용 계정 (가상)

처음 켜면 아래 계정이 자동으로 만들어져요. (실제 사람과 관련 없는 시험용이에요.)

| 역할 | 아이디 | 비밀번호 |
|---|---|---|
| 총관리자(사장님) | `master` | `Master#2026` |
| 일반관리자(관리사 **강다은**과 이어짐) | `staff01` | `Staff#2026` |
| 고객 | `customer01` | `Customer#2026` |

## 확인 주소

| 주소 | 내용 |
|---|---|
| `/health` | 서버와 DB 연결 확인(로그인 없이). 정상이면 `{"status":"정상", ...}` |
| `/options` | 견종·성별·스타일 같은 선택 목록(로그인 없이) |
| `/stats`, `/stats/series` | 예약 현황 숫자와 그래프용 숫자 (관리자 화면 역할) |
| `/auth/login`, `/auth/signup` | 로그인, 고객 가입(로그인 없이) |
| `/me/...` | 고객 전용 (내 정보·내 강아지·내 예약·예약 가능 시간) |

그 밖의 주소는 로그인(출입증)이 있어야 해요.

## 설정값 (환경 변수)

값은 **서버 설정 화면이나 `.env` 파일에만** 넣어요. `.env`는 GitHub에 올라가지 않아요. 예시는 [.env.example](./.env.example)에 있어요.

| 이름 | 뜻 | 예시 |
|---|---|---|
| `DATABASE_URL` | PostgreSQL 접속 주소 (Level 1과 같은 DB) | `postgresql://사용자:비밀번호@주소/DB이름` |
| `JWT_SECRET` | 로그인 출입증을 만드는 비밀 문장. 길고 아무도 모르는 값으로 | (임의의 긴 문장) |
| `GPT_API_KEY` | AI 미용 도우미용 OpenAI 키. 비워 두면 "AI 기능을 준비 중이에요"라고 안내 | `sk-...` |
| `GPT_MODEL` | (선택) 쓸 모델 이름 | `gpt-4o-mini` |
| `CORS_ORIGIN` | 이 서버를 불러도 되는 화면(프론트) 주소. 쉼표로 여러 개 | `https://내-앱.vercel.app` |
| `PORT` | 서버 포트. Render가 자동으로 넣어 줘요 | `4100` (내 컴퓨터용) |
| `NODE_VERSION` | (Render) 쓸 Node 버전 | `22` |

## 내 컴퓨터에서 실행

```bash
npm install
cp .env.example .env     # .env 를 열어 값을 채워 주세요
npm run start:dev
```

서버: http://localhost:4100 · 확인: http://localhost:4100/health

## Render에 올리기

1. Render에서 **New → Web Service**를 고르고 이 저장소를 연결해요.
2. 아래처럼 적어요.

| 칸 | 값 |
|---|---|
| Language | Node |
| Build Command | `npm install && npm run build` |
| Start Command | `npm run start:prod` |
| Instance Type | Free |

3. **Environment**에 위 표의 `DATABASE_URL`, `JWT_SECRET`, `GPT_API_KEY`, `CORS_ORIGIN`, `NODE_VERSION`을 넣어요.
4. 배포가 끝나면 `https://내-서버주소.onrender.com/health`가 `"정상"`인지 확인해요.

> **Level 1과 같은 DB를 써요.** 고객·강아지·미용 기록은 두 사이트가 함께 보고 바꿔요. 이 서버를 처음 켜면 DB에 새 테이블을 더하고, 이전 역할 이름(관리자·일반)은 총관리자·일반관리자로 자동으로 바꿔요. Level 1 테이블의 구조는 바꾸지 않아요. Level 1에는 로그인이 없어서 그 주소로는 누구나 같은 데이터를 지울 수 있어요. 예약이 있는 강아지·관리사는 Level 1에서도 지워지지 않아요. DB의 사용 기간이 끝나면 두 사이트가 함께 멈춰요.
